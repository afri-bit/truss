# 0014. Branch prefixes, commit identity and the release gate

- Status: Proposed
- Date: 2026-11-13

## Context

The maintainer asked for three repository rules to be hard, meaning enforced by tools rather than
by convention:

1. A branch may only be created with the prefix `bugfix`, `feature`, `hotfix`, `release`, `task`
   or `chore`. Nothing else, `claude/` included.
2. Every commit uses the afri-bit identity. A `Co-authored-by` trailer may be allowed.
3. A semver tag triggers a release that refuses to publish unless the Go version, the TRUSS
   Desktop version and the changelog agree with the tag, and that builds Linux, Windows and macOS
   binaries and creates a GitHub release with the changelog and the notes GitHub generates.

The constitution (2.0.0) allowed only `feature/`, `bugfix/` and `hotfix/`, exempted `claude/`
harness branches in the agent gate, and said "no `Co-authored-by`". The release workflow already
checked the tag against `go.mod` and `CHANGELOG.md`, built six binaries and called
`gh release create --generate-notes`, but it did not check the version the binary prints, TRUSS
Desktop had no version of its own, and the changelog headings were free text.

## Decision

**Branch prefixes.** `.github/scripts/branch-name-check.sh` holds the one rule:
`<type>/<name>`, type one of the six, name lowercase and hyphenated; `main` and `develop` pass.
It is used in three places: `guard-git.sh` (an agent cannot create a branch that breaks it), the
`repo-rules` workflow (red check on every push and pull request), and the agent gate G1, which no
longer exempts `claude/`. The constitution is amended to 2.1.0 (Branching).

**Commit identity.** The author name is `afri-bit` and the author email is not a tool address.
`guard-git.sh` refuses `git commit` under any other identity, `commit-identity-check.sh` runs in
`repo-rules` over every non-merge commit of a pull request, and the SessionStart hook warns early.
`Co-authored-by` is allowed and never required; `Signed-off-by`, session links and "generated by"
lines stay forbidden. MEM-0001 is superseded.

**Release gate.** The release check now compares the tag with four declarations: `// version:` in
`go.mod`, `const Version` in `cmd/truss/version.go` (what `truss version` prints),
`internal/webui/VERSION` (TRUSS Desktop, a file of its own so the two can be bumped from separate
places) and the latest `CHANGELOG.md` section, which must be dated with the tag date and may only
use the Keep a Changelog headings Added, Changed, Deprecated, Removed, Fixed and Security. The
rest of the workflow is unchanged: CI must pass, six binaries are built (Linux, macOS, Windows,
amd64 and arm64, `CGO_ENABLED=0`), and the release is created with the changelog section followed
by the notes the GitHub release-notes API generates (contributors and history).

TRUSS Desktop is still embedded in the `truss` binary and served by the daemon, so its version is
checked against the tag but is not yet shown on screen or reported by an API. Showing it is a
separate change.

## Consequences

- Good: the three rules fail loudly, early (the agent's own command) and late (CI).
- Good: a release cannot go out with a `truss version` that disagrees with its tag.
- Bad: the pipeline's tag, Go version and Desktop version move in lock step for now; a release that
  changes only Desktop still bumps all of them.
- The harness for cloud sessions starts on a `claude/...` branch. It now fails `repo-rules`. The
  work has to be moved to a correctly named branch (`git switch -c task/<name>`) before a pull
  request is opened.
- Hooks and workflows do not stop a push from someone who bypasses them. A GitHub **branch ruleset**
  is the real gate and is a manual step for the maintainer: restrict branch names to
  `^(bugfix|feature|hotfix|release|task|chore)/[a-z0-9][a-z0-9._-]*$` (plus `main` and `develop`),
  and require the `Branch name` and `Commit identity` checks on `develop` and `main`.
- Existing history is not rewritten: commits before this change keep their authors, and the
  check only looks at the commits of the pull request in front of it.

Rejected: calling the release-notes REST endpoint by hand (the `gh release create --generate-notes`
flag calls the same API and is already in use); a separate tag per component for Desktop (more
ceremony than one product needs today); exempting `claude/` in CI (the maintainer asked for no
exceptions).
